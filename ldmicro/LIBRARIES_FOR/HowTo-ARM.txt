
	Test LdMicro for ARM STM32 microcontrollers :
	_____________________________________________


	If everything is well configured, one can generate C files,
	hex file, and upload it to the target without exiting LdMicro



1)	Install EmIde (for instance) or install directly an arm-gcc for windows 

2)	Copy LdMicro executable, buildArm.bat and flashMCU.bat in a same directory
	Also copy LIBRARIES_FOR directory and its content at the same place
	Verify that libraries' version is the same as LdMicro's one

3)	Edit buildArm.bat (right click + Modify) and modify GCCPATH to point 
	to your arm-gcc path

	Then, edit if need be FlashMCU.bat (right click + Modify) 
	According to the emulator you intend to use, you can modify instructions 
	that will load the hex file into the target
	It'll be possible anyway to flash the target manually with hex file

4)	Create a ladder with LdMicro in a directory.

5)	Compile the ladder with "Compile ARM-GCC" 
	and generate the C file in the same directory as the source (.ld) 
	file, with the same name (.c)
	
	It also generates a (.h) file and a ladder.h header
	With joined libraries, it makes a ready-made C project

6)	Launch "Generate C solution" from LdMicro to get the hex file
	in "bin" directory

	Look at the command window ; there shouln't be compiling errors
	Librairies are automaticaly copied (first time only) in "lib" 
	subdirectory where they can be adapted if need be
	Intermediate files are generated in "obj" subdirectory

7)	Upload generated hex file into the target with "Call FlashMcu" or manually
	Test generated hex file on target...



NB:	The libraries (derived from T. Merjeles') have been tested on STM32F407
	The name of the target is defined in ladder.h as LDTARGET_stm32f40x

	You can use several ADCs or PWMs, but only one Uart, one SPI and one I2C
	(But with several peripherals with different software SS pins on SPI
	or with diferent addresses on I2C Bus)

NB:	SPI must be named "SPI1", "SPI2" or "SPI3" on ARMs
	SPI new functions are:
	SPI Send/Receive, which sends and/or receives a byte 
	SPI Write, which send an alphanumerical string to SPI without reception

	SPI frequency is defined as UART's one in the global settings
	SPI works only in master mode with most standard config

NB:	I2C must be called "I2C1", "I2C2" or "I2C3" on ARMs
	I2C new functions are:
	I2C Read, to read one byte in a peripheral's register
	I2C Write, to write a byte to a peripheral's register

	I2C frequency is also defined in global settings
	I2C also works only in master mode

NB:	ADC max available resolution is used
	PWM max resolution is used and parameter is only % between 0 and 100

NB:	Supported STM32 boards and target name (used by buildArm.bat):

	STM32F40X 144-LQFP                     -> stm32f40x   (STM32F4 libraries)
	STM32F411 48-UFQFPN / WeAct BlackPill  -> stm32f411   (STM32F4 libraries,
		25 MHz crystal, linker script CortexM4_F411.ln)
	STM32F10X 48-LQFP / Bluepill (C8/CB)   -> stm32f10x   (STM32F1 libraries)
	STM32F103C6 48-LQFP / Bluepill         -> stm32f103c6 (STM32F1 libraries,
		32 KB Flash / 10 KB RAM, linker script CortexM3_C6.ln)

	STM32F411 BlackPill: UART1 = PA9 (TX) + PA10 (RX), UART2 = PA2 + PA3,
	SPI1 = PA5/PA6/PA7, SPI3 = PB3/PB4/PB5, I2C1 = PB8 (SCL) + PB9 (SDA),
	PWM on PA8..PA11 (TIM1), PA0..PA3 (TIM2) and PB6..PB9 (TIM4),
	ADC1 on PA0..PA7, PB0 and PB1. On-board LED on PC13 (active low).

	STM32F103C6: there is no TIM4, USART3, I2C2 or SPI2.
	UART1 = PA9 (TX) + PA10 (RX), UART2 = PA2 + PA3, SPI1 = PA4..PA7,
	I2C1 = PB6 + PB7, PWM on PA8..PA11 (TIM1) and PA0..PA3 (TIM2).

	Timer 3 is reserved for the PLC cycle on all of them.

NB:	ST NUCLEO-L432KC (STM32L432KC) -> target stm32l432 (STM32L4 libraries)

	The libraries of LIBRARIES_FOR/Arm/STM32L4 are written directly on the
	CMSIS device headers of ST (the "Standard Peripheral Library" used by
	STM32F1 and STM32F4 does not exist for the L4 family).

	Clock: internal HSI16 oscillator + PLL = 80 MHz. No crystal is needed
	and the "MCU crystal frequency" value of LDmicro has no effect on the
	cycle time: the library computes it from the real clock.

	PLC cycle: Timer 7 (there is no Timer 3 in the STM32L432; the
	configuration dialog still shows "3" for every ARM target).

	UART:  USART2 = PA2 (TX) + PA15 (RX). It is the virtual COM port of the
	       on-board ST-Link: no USB-serial adapter is needed.
	SPI:   SPI1 = PB3 (SCK, D13) + PB4 (MISO, D12) + PB5 (MOSI, D11).
	       PB3 is also the LD3 LED of the board.
	I2C:   I2C1 = PB6 (SCL, D5) + PB7 (SDA, D4), with external pull-ups.
	       Solder bridges SB16 and SB18 tie PB7 to PA5 (A4) and PB6 to
	       PA6 (A5) by default: do not drive PA5/PA6 while using the I2C.
	PWM:   PA8 (D9), PA9 (D1), PA10 (D0), PA11 (D10) on Timer 1;
	       PA0 (A0), PA1 (A1), PA2 (A7), PA3 (A2) on Timer 2.
	ADC:   PA0..PA7 (A0, A1, A7, A2, A3, A4, A5, A6) and PB0 (D3), 12 bits.

	PC14/PC15 (D7/D8) are used by the 32.768 kHz crystal and are not
	offered as I/O. Flashing: on-board ST-Link (flashMcu.bat), or copy the
	.bin file to the USB drive created by the Nucleo.

NB:	WeAct Studio STM32G431 Core Board (STM32G431CBU6) -> target stm32g431
	(STM32G4 libraries, written on the CMSIS device headers of ST)

	Clock: internal HSI16 oscillator + PLL = 80 MHz. The 8 MHz crystal and
	the 170 MHz "boost" mode are not used; the "MCU crystal frequency"
	value of LDmicro has no effect on the cycle time.

	PLC cycle: Timer 7 (the configuration dialog shows "3").

	UART:  USART2 = PA2 (TX) + PA3 (RX).
	SPI:   SPI1 = PA5 (SCK) + PA6 (MISO) + PA7 (MOSI).
	I2C:   I2C1 = PA15 (SCL) + PB7 (SDA), with external pull-ups.
	PWM:   Timer 1: PA8, PA9, PA10, PA11
	       Timer 2: PA0, PA1, PB10, PB11
	       Timer 3: PC6 (on-board LED), PB5, PB0, PB1
	       Timer 4: PB6, PB9
	ADC:   ADC1: PA0, PA1, PA2, PA3, PB0, PB1, PB11, PB12, PB14
	       ADC2: PA5, PA6, PA7, PC4, PB15            (12 bits)

	LED on PC6 (active high). KEY button on PC13 (high when pressed: use
	the input without pull-up). BOOT0 button on PB8.
	PF0/PF1 and PC14/PC15 are used by the crystals.

	Flashing (flashMcu.bat): STM32CubeProgrammer with an ST-Link on the
	SWD pins, or through USB (DFU) holding BOOT0 while resetting.
