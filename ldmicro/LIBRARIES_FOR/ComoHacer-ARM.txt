
	Probar LdMicro en ARMs (STM32) :
	________________________________


1) 	Instale EmIde for ARMs o instale directamente un arm-gcc para Windows 


2) 	Copie el ejecutable LdMicro, buildArm.bat y flashMCU.bat en un mismo directorio,
	y copie las bibliotecas de C LIBRARIES_FOR en el mismo directorio

3) 	Edite buildArm.bat (haga clic con el botón derecho + Modificar) y modifique 
	GCCPATH para que apunte a su ruta arm-gcc

	Si pretende utilizar directamente un programador para flashear el objetivo, 
	debe configurar las líneas de comandos en FlashMCU.bat
	De todos modos, será posible flashear el objetivo manualmente a continuación

4) 	Cree una escalera con LdMicro en un directorio

5) 	Compile la escalera con "Compile en ARM-GCC por 32-bit ARM"
	y genere el archivo C en el mismo directorio que el Archivo fuente (.ld), 
	con el mismo nombre (.c)

	También genera un archivo (.h) y un encabezado ladder.h
	Con bibliotecas unidas, realiza un proyecto de C ya confeccionado

6) 	Inicie "Generar C solución" desde LdMicro para obtener el archivo hex
	en el directorio "bin"

	Mira la ventana de comandos ; no debe haber errores de compilación
	Las bibliotecas se copian automáticamente (la primera vez) en lel subdirectorio 
	"lib" donde pueden ser adaptadas
	Los archivos intermedios se generan en el subdirectorio "obj"

7) 	Flashea el objetivo con "Llamar FlashMcu" o manualmente
	Prueba de archivo hexadecimal generado en destino ...



NB: 	Las bibliotecas han sido probadas en STM32F07
	Es posible (y fácil) adaptar el código a otros objetivos del
	La misma familia mediante el uso de directivas de compilación.
	El nombre del objetivo se define en ladder.h como LDTARGET_stm32f40X

	Puede usar varios ADC o PWM, pero solo un Uart, un SPI y un I2C
	(Pero con varios periféricos con diferentes pines SS de software en SPI
	o con diferentes direcciones en bus I2C)

NB: 	SPI debe llamarse "SPI1", "SPI2", o "SPI3" en los STM32F4
	Las nuevas funciones de SPI son:
	SPI Enviar / Recibir, que envía y / o recibe un byte
	SPI Write, que envía una cadena alfanumérica a SPI sin recepción

	La frecuencia SPI se define como la de UART en la configuración global
	SPI funciona solo en modo maestro con la mayoría de las configuraciones estándar

NB: 	I2C debe llamarse "I2C1", I2C2" o I2C3" en los ARM
	Las nuevas funciones de I2C son:
	I2C Leer, para leer un byte en un registro de periféricos
	I2C Escribir, para escribir un byte en un registro de periféricos

	La frecuencia I2C también se define en la configuración global
	I2C también funciona solo en modo maestro

NB: 	Se utiliza la resolución máxima ADC disponible.
	Se utiliza la resolución máxima de PWM y el parámetro es solo% entre 0 y 100

NB:	Placas STM32 soportadas y nombre de destino (lo usa buildArm.bat):

	STM32F40X 144-LQFP                     -> stm32f40x   (librerias STM32F4)
	STM32F411 48-UFQFPN / WeAct BlackPill  -> stm32f411   (librerias STM32F4,
		cristal de 25 MHz, enlazador CortexM4_F411.ln)
	STM32F10X 48-LQFP / Bluepill (C8/CB)   -> stm32f10x   (librerias STM32F1)
	STM32F103C6 48-LQFP / Bluepill         -> stm32f103c6 (librerias STM32F1,
		32 KB Flash / 10 KB RAM, enlazador CortexM3_C6.ln)

	STM32F411 BlackPill: UART1 = PA9 (TX) + PA10 (RX), UART2 = PA2 + PA3,
	SPI1 = PA5/PA6/PA7, SPI3 = PB3/PB4/PB5, I2C1 = PB8 (SCL) + PB9 (SDA),
	PWM en PA8..PA11 (TIM1), PA0..PA3 (TIM2) y PB6..PB9 (TIM4),
	ADC1 en PA0..PA7, PB0 y PB1. LED de la placa en PC13 (activo a nivel bajo).

	STM32F103C6: no tiene TIM4, USART3, I2C2 ni SPI2.
	UART1 = PA9 (TX) + PA10 (RX), UART2 = PA2 + PA3, SPI1 = PA4..PA7,
	I2C1 = PB6 + PB7, PWM en PA8..PA11 (TIM1) y PA0..PA3 (TIM2).

	En todas ellas el Timer 3 queda reservado para el ciclo del PLC.

NB:	ST NUCLEO-L432KC (STM32L432KC) -> destino stm32l432 (librerias STM32L4)

	Las librerias de LIBRARIES_FOR/Arm/STM32L4 estan escritas directamente
	sobre las cabeceras CMSIS de ST (para la familia L4 no existe la
	"Standard Peripheral Library" que usan STM32F1 y STM32F4).

	Reloj: oscilador interno HSI16 + PLL = 80 MHz. No hace falta cristal y
	el valor "Frecuencia del cristal" de LDmicro no influye en el tiempo de
	ciclo: la libreria lo calcula a partir del reloj real.

	Ciclo del PLC: Timer 7 (el STM32L432 no tiene Timer 3; el dialogo de
	configuracion sigue mostrando "3" para todos los ARM).

	UART:  USART2 = PA2 (TX) + PA15 (RX). Es el puerto COM virtual del
	       ST-Link de la placa: no hace falta adaptador USB-serie.
	SPI:   SPI1 = PB3 (SCK, D13) + PB4 (MISO, D12) + PB5 (MOSI, D11).
	       PB3 es tambien el LED LD3 de la placa.
	I2C:   I2C1 = PB6 (SCL, D5) + PB7 (SDA, D4), con resistencias externas.
	       Los puentes SB16 y SB18 unen de fabrica PB7 con PA5 (A4) y PB6
	       con PA6 (A5): no use PA5/PA6 como salidas mientras use el I2C.
	PWM:   PA8 (D9), PA9 (D1), PA10 (D0), PA11 (D10) con el Timer 1;
	       PA0 (A0), PA1 (A1), PA2 (A7), PA3 (A2) con el Timer 2.
	ADC:   PA0..PA7 (A0, A1, A7, A2, A3, A4, A5, A6) y PB0 (D3), 12 bits.

	PC14/PC15 (D7/D8) estan ocupados por el cristal de 32.768 kHz y no se
	ofrecen como E/S. Grabacion: ST-Link de la placa (flashMcu.bat), o
	copiando el archivo .bin a la unidad USB que crea la Nucleo.

NB:	WeAct Studio STM32G431 Core Board (STM32G431CBU6) -> destino stm32g431
	(librerias STM32G4, escritas sobre las cabeceras CMSIS de ST)

	Reloj: oscilador interno HSI16 + PLL = 80 MHz. No se usa el cristal de
	8 MHz ni el modo "boost" de 170 MHz; el valor "Frecuencia del cristal"
	de LDmicro no influye en el tiempo de ciclo.

	Ciclo del PLC: Timer 7 (el dialogo de configuracion muestra "3").

	UART:  USART2 = PA2 (TX) + PA3 (RX).
	SPI:   SPI1 = PA5 (SCK) + PA6 (MISO) + PA7 (MOSI).
	I2C:   I2C1 = PA15 (SCL) + PB7 (SDA), con resistencias externas.
	PWM:   Timer 1: PA8, PA9, PA10, PA11
	       Timer 2: PA0, PA1, PB10, PB11
	       Timer 3: PC6 (LED de la placa), PB5, PB0, PB1
	       Timer 4: PB6, PB9
	ADC:   ADC1: PA0, PA1, PA2, PA3, PB0, PB1, PB11, PB12, PB14
	       ADC2: PA5, PA6, PA7, PC4, PB15            (12 bits)

	LED en PC6 (activo a nivel alto). Tecla KEY en PC13 (da nivel alto al
	pulsarla; configure la entrada sin pull-up). Tecla BOOT0 en PB8.
	PF0/PF1 y PC14/PC15 estan ocupados por los cristales.

	Grabacion (flashMcu.bat): STM32CubeProgrammer con un ST-Link en los
	pines SWD, o por USB (DFU) manteniendo BOOT0 pulsada al reiniciar.

NB:	Arduino Nano R4 (Renesas RA4M1, R7FA4M1AB3CFM) -> destino ra4m1
	(librerias RA4M1, escritas sobre la cabecera CMSIS de Renesas)

	Reloj: oscilador interno HOCO = 48 MHz; el valor "Frecuencia del
	cristal" de LDmicro no influye en el tiempo de ciclo.

	Ciclo del PLC: temporizador GPT6 (el dialogo muestra "3").

	Puertos: el RA4M1 numera sus puertos. LDmicro muestra P0xx como puerto
	A, P1xx como B, P2xx como C, P3xx como D y P4xx como E; la lista de
	pines da ademas el nombre Renesas y el nombre Arduino ("P104 D3"). Los
	numeros de pin son los del conector de la Nano (1 = D1/TX, 2 = D0/RX,
	5 = D2 ... 16 = D13, 19 = A0 ... 26 = A7); 31 = LED, 32/33/34 = LED
	rojo/verde/azul.

	UART:  SCI2 = D1 (TX) + D0 (RX). El USB de la placa no es un puerto
	       serie para el programa PLC: use un adaptador USB-serie.
	SPI:   SPI1 = D13 (SCK) + D12 (MISO) + D11 (MOSI).
	I2C:   IIC1 = A5 (SCL) + A4 (SDA), con resistencias externas.
	PWM:   GPT0: D7, D6      GPT1: D11, D3     GPT2: D4, D5
	       GPT3: D13, D10    GPT4: D1, D0      GPT7: D8, D9
	       GPT5: LED rojo. Las dos salidas de un temporizador comparten
	       la frecuencia.
	ADC:   A0..A7, D4 y D5, 12 bits.
	Este MCU no tiene resistencias pull-down, solo pull-up.

	Grabacion (flashMcu.bat): por USB con dfu-util y el bootloader de la
	placa (pulse reset dos veces). El programa se enlaza en 0x4000 y el
	bootloader se conserva: la placa puede volver al IDE de Arduino cuando
	quiera. Mientras corre el programa PLC la placa no aparece como
	dispositivo USB.

NB:	PIC32CM LS00 Curiosity Nano+ Touch (Microchip PIC32CM5164LS00048, Cortex-M23)
	-> destino pic32cm_ls00 (librerias PIC32CM_LS00, con su propia cabecera
	de registros)

	Compilador: el Cortex-M23 necesita arm-none-eabi-gcc 7 o posterior;
	buildArm.bat busca "GNU Tools ARM Embedded\7 2018-q2-update" (edite
	GCC_PATH para otra version). El compilador de emIDE V2.20 no sirve
	para este destino.

	Reloj: oscilador interno OSC16M a 16 MHz; el valor "Frecuencia del
	cristal" de LDmicro no influye en el tiempo de ciclo.

	Ciclo del PLC: temporizador TC0 (el dialogo muestra "3").

	Puertos: LDmicro maneja 16 pines por puerto, asi que los puertos de 32
	pines se dividen:
	puerto A de LDmicro = PA00..PA15, puerto B = PB00..PB15,
	puerto C de LDmicro = PA16..PA31, puerto D = PB16..PB31.
	La lista de pines da el nombre real ("PA23 SW"). Los numeros de pin son
	los del encapsulado de 48 pines.

	Placa: LED en PA15 (enciende con la salida en bajo), pulsador en PA23
	(a masa: active el pull-up de la entrada).

	UART:  SERCOM3 = PB08 (TX) + PB09 (RX) = puerto COM virtual de la placa:
	       el programa PLC habla con el PC por el cable USB.
	SPI:   SERCOM0 = PA05 (SCK) + PA07 (MISO) + PA04 (MOSI).
	I2C:   SERCOM1 = PA17 (SCL) + PA16 (SDA), con resistencias externas.
	PWM:   TCC0: PA08, PA15 (LED), PA18, PA19     TCC1: PA10, PA11
	       TCC2: PA12, PA13                       TCC3: PB22, PB23, PB02, PB03
	       Las salidas de un temporizador comparten la frecuencia.
	ADC:   PA02..PA11, PB02, PB03, PB08, PB09; 12 bits, referencia =
	       alimentacion.

	TrustZone: el programa PLC corre por completo en estado seguro, enlazado
	en la direccion 0. Necesita una placa cuyos fusibles de configuracion
	(user row y boot configuration row) dejen suficiente Flash segura para
	el programa; LDmicro no toca los fusibles. Si una demo TrustZone los
	cambio, restaurelos con MPLAB X.

	Grabacion (flashMcu.bat): el archivo hex se copia a la unidad CURIOSITY
	del depurador de la placa. Tambien se puede usar MPLAB X IPE.
